# Архитектура YieldFlow ERP

Демо-система учёта птицефабрики: Angular-приложение (интерфейс) и NestJS-сервер с базой PostgreSQL.

```
Браузер (Angular 22, Vercel)
   │  HTTPS, заголовок Authorization: Bearer <JWT>
   ▼
NestJS API (Render)  ──►  PostgreSQL (Neon)
```

Сейчас на сервере два раздела: **птичники** и **склад яйца**. Остальные семь разделов пока хранят данные в браузере (`persistedSignal`) и переедут на сервер на следующем этапе.

## Сервер (`backend/`)

Код разложен по модулям Nest. Каждый модуль отвечает за свою область:

| Модуль | Ответственность |
|---|---|
| `auth` | вход по логину и паролю, выдача и проверка JWT, глобальная защита адресов |
| `users` | таблица пользователей, поиск по логину |
| `houses` | птичники, суточные отчёты, приём молодняка, убытие птицы |
| `egg-warehouse` | партии яйца, остатки по категориям, сортировка |
| `demo` | первичное заполнение базы и сброс демо-данных |
| `config` | чтение и проверка переменных окружения |
| `health` | проверка «сервер жив» и «база отвечает» |

В каждом модуле одна и та же цепочка: **контроллер** (принимает запрос) → **сервис** (бизнес-правила) → **репозиторий TypeORM** (доступ к базе). Входные данные описаны классами DTO с правилами проверки; запрос с лишними или неверными полями отклоняется ответом 400 ещё до сервиса.

### Решения и причины

**Закрыто по умолчанию.** `JwtAuthGuard` подключён глобально: токен нужен на любом адресе, кроме помеченных `@Public()` (вход и `/health`). Забыть закрыть новый адрес невозможно.

**Пароли и токены.** Пароль хранится только как хеш bcrypt. Колонка хеша помечена `select: false`, поэтому случайно попасть в ответ API она не может. При неверном логине и при неверном пароле сервер отвечает одинаково и за одинаковое время. На каждом запросе проверяется, что пользователь существует и активен: отключённый сотрудник теряет доступ сразу, не дожидаясь конца срока токена. Вход ограничен 5 попытками в минуту.

**Транзакции и блокировки.** Сортировка партии яйца — это три действия: пометить партию, добавить яйцо в остатки, записать результат. Они выполняются в одной транзакции; строка партии блокируется (`SELECT ... FOR UPDATE`). Если два запроса придут одновременно, второй дождётся первого, увидит статус «рассортирована» и получит 409, а остатки вырастут ровно один раз. Это проверяет сквозной тест на 10 одновременных запросов; без блокировки он падает (проверено). Суточный отчёт и приём молодняка защищены так же.

**Остатки считает база.** Добавление к остатку выполняется одним запросом `INSERT ... ON CONFLICT DO UPDATE SET count = count + N`, а не «прочитать, прибавить, записать».

**Схема базы меняется только миграциями.** `synchronize` выключен. Миграция применяется при старте сервера. Идентификаторы создаёт сама база (`gen_random_uuid()`), расширения не нужны.

**Бизнес-правила на сервере, не в интерфейсе.** Сервер не даёт внести падёж больше поголовья, яйцо в птичнике молодняка или яйценоскость выше 100%. Интерфейс тоже проверяет это, но доверять только ему нельзя.

**Настройки.** Все секреты приходят из переменных окружения и проверяются при запуске. Слабый секрет или отсутствующая настройка останавливают запуск с понятным сообщением.

## Интерфейс (`src/app/`)

- **Вход и защита страниц.** `AuthService` хранит токен в сигнале и в `localStorage`. `authGuard` закрывает все страницы, кроме `/login`, и запоминает, куда шёл человек. `authInterceptor` добавляет токен только к запросам к нашему API (чужие сайты его не получают) и выходит из системы при ответе 401.
- **Данные.** `PoultryManagementService` и `EggWarehouseService` хранят данные с сервера в сигналах, поэтому экраны обновляются мгновенно. Публичные названия сервисов не менялись, и остальные разделы работают без правок. Данные загружаются, когда человек вошёл, и очищаются при выходе.
- **Холодный старт.** Бесплатный сервер засыпает. Страница входа сразу делает запрос `/api/health` и показывает состояние сервера, пока человек вводит пароль.
- **Защита от подмены адреса.** После входа человека возвращают на страницу, куда он шёл, но только если это внутренний путь приложения; адрес вида `//чужой-сайт` игнорируется.
- **Токен в `localStorage`.** Это просто, но токен доступен скриптам страницы (риск при XSS). Более защищённый вариант — httpOnly-cookie, он потребует доработки сервера.

## Тесты
